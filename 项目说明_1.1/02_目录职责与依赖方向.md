# 目录职责与依赖方向

依据当前真实布局，不重新设计代码目录。当前 Git 根是唯一完整现行版本；完整源码备份只能放项目外。

## 放置与访问规则

| 现有位置 | 应该放什么 | 不应该放什么 |
| --- | --- | --- |
| 根目录 | `启动程序.py`、`运行配方研发.py`、依赖/工程声明、README 与许可入口 | 运行/临时产物、新代码外壳、内部设计副本或科研计划需求 |
| `核心系统/` | 插件装配与流程编排、共用数据管理、校验、规则引擎、确认批次/用途存取 | UI 交互、具体外部数据库 Provider、Agent 依赖 |
| `核心系统/候选表输入.py` | CSV/XLSX 安全校验与解析，UI 预览和正式导入共用 | 字段映射、保存数据、运行目录或具体插件依赖 |
| `设置/颅骨透明化用途设置.py` | 用途元数据及默认用途配置 | 用途算法、HSP 或配方评价 |
| `设置/规则注册设置.py` | 唯一默认属性/规则预设与显式工厂 | 规则执行算法、持久化或第二套规则引擎 |
| `核心系统/默认装配.py` | 功能插件注册、显式 legacy alias、默认专用实现与物性注册表依赖装配 | 业务执行、用户数据读取、运行状态或全局服务容器 |
| `核心系统/公开证据/` | Provider/Repository/身份/证据/请求契约、Resolver、条件/单位/身份标准化与冲突解析、执行桥派生视图 | 具体 Provider、依赖某来源内部字段的业务调用 |
| `核心系统/目标规格/` | Target Profile 数据校验、不可变编辑、JSON 存取、纯指标绑定及执行计划编译/预检 | 查询候选库/Benchmark、执行模型、UI 或跨模块调度 |
| `核心系统/分子标准化/` | 工具无关标准化请求、步骤、结果及 MoleculeStandardizer；不改 observed 身份 | RDKit 算法、网络和身份归并 |
| `核心系统/分子属性/` | 工具无关核心2D指标、独立 Descriptor Engine 契约与计算器Protocol | RDKit导入、结构搜索、身份归并、规则引擎或配方性质 |
| `插件/数据导入/`、`数据合并/` | 导入与身份适配、属性合并/冲突检测 | 另一套公开来源查询系统或上层业务编排 |
| `插件/化学计算/`、`筛选与评价/` | 化学计算、规则/证据评价、特征与报告 | 对其他功能插件私有实现的隐藏调用 |
| `插件/公开数据/` | 公开聚合功能入口、兼容转换与缓存迁移；`providers/<来源>/` 按 client/parser/mapping/provider 分工放置具体实现 | Provider 互调、直接改 UI、覆盖 descriptor 宽表 |
| `插件/配方生成/` | 输入组装、组合生成、比例细化、发现约束、候选排序 | 跨功能搜索循环、Benchmark 泄漏到独立发现池 |
| `插件/配方物性/` | 输入/结果/模型接口、注册与汇总；模型放入折射率/黏度/扩散/渗透/水活度现有分类 | 用途阈值、毒理结论或模型反调功能插件 |
| `插件/颅骨透明化/颅骨透明化功能插件.py` | 消费用途设置，执行成分/配方/终点与约束评价 | 反向调用核心编排、将当前用途假设固化到公共层 |
| `插件/透明化预测/`、`实验优化/`、`结果展示/` | 现有预测/优化接口及其真实实现、可视化 | 将占位声明当已实现能力或伪造预测 |
| `设置/` | 现有配置、显式样例及验证资料 | 为运行补造实验值、把验证标签当候选种子 |
| `数据/` | 论文原件、用户原件、软件数据库、各类结果、实验记录和运行隔离数据 | 业务实现、跨模块未经声明的临时通信格式 |
| `软件界面/` | 输入与展示、调用核心公开流程、页面所需状态 | 业务算法、底层依赖的 session state、插件间调度 |
| `测试/` | 根层单元/契约测试、SeeThrough回归测试、界面端到端测试、benchmark工具、fixtures/seethrough；Git 按明确目录单层白名单 | 大型结果、源码副本、pytest 临时项目、默认联网、一次性发布脚本 |
| `审计结果/benchmark/<run_id>/` | 需保留的科学验证/benchmark 结果、原始下载、冻结配置、单个 runner 与依赖快照、报告和 ZIP | 作为当前源码、完整项目副本、自动过期删除 |
| `审计结果/legacy/` | 旧根运行记录与旧骨架检查资料，仅供明确历史查阅 | 正式运行写入目标或当前架构依据 |
| `.cache/`、系统 TEMP | 可再生缓存、短期临时文件；pytest 使用项目外临时根 | 正式证据、用户原件或 retained run |
| `项目说明_1.1/` | 唯一内部说明，沿用 00–07，`模块/` 保存公开证据、Target Profile、配方物性、结构查询、分子属性、分子标准化正文 | 第二套架构或旧版本历史堆积 |
| `.venv/` | 本地依赖环境 | 项目实现或新需求 |

用户导入、SeeThrough 复现与 CLI 验证/发现共用 `数据/运行记录/run_YYYYMMDDTHHMMSSZ_<随机ID>/`；CLI 不再创建根运行记录目录。系统 TEMP/TMP 承担真正临时文件，`.cache/temp/` 仅用于明确保留调试内容。SeeThrough 补充数据2/3入口每次新建 run，统一记录/中间结果/报告/图表均随本轮保存。固定论文结果仅保留历史浏览兼容，不作为活动 run 缺失文件的 fallback；确认/用途 CSV 仍全局存储。

benchmark 的 freeze/acquire/rank、参考提取、评价、报告入口都先通过 `测试/benchmark工具/benchmark_artifacts.py` 校验输出位置。报告导入无读写副作用，报告及归档必须显式生成且拒绝覆盖。冻结单个执行脚本用于复现，不是第二套源码。正式记录、benchmark、科学审计和模型产物默认保留；不提供启动自动清理或一刀切删除。

`.gitignore` 管 Git 白名单，`.ignore` 管默认搜索，输出入口管落盘位置。三者分别维护；`.ignore` 默认排除所有数据、审计、运行、模型、缓存和依赖环境，必要 fixture 按精确路径读取。

## 依赖方向

入口/页面 → 核心公开流程 → 功能插件接口/装配实例。功能插件 → 共用数据契约与存取接口、自身策略。公开聚合 → PublicDataProvider/ProviderRegistry、EvidenceRepository、EvidenceResolver；公共证据层不导入具体 Provider。物性汇总 → 物性模型接口及其声明依赖；策略之间不直接互调。

业务流程不得把具体插件构造重新散回自身文件；默认选择集中到 `核心系统/默认装配.py`，控制器兼容工厂委托它创建管理器。装配工厂注册具体实现是正常依赖；其他业务模块不得依赖仓库内部数据库结构。页面不再 import 具体插件或穿透管理器；当前剩余用途绑定，见 [07](07_技术债与遗留预留.md)，不是允许方向的例外授权。

旧 `颅骨透明化用途插件.py` 只导出正式功能插件及核心历史运行器；内部算法调用使用 `颅骨透明化功能插件.py`，元数据读取使用 `设置/颅骨透明化用途设置.py`，避免普通插件反向依赖编排。粗搜和比例细化共用 `配方生成/配方定义构建.py::组装定义`；旧自动组合模块只重导出该函数。UI 调用 `配方评估流程.解析物性配置`。

## 新增与替换文件

先确认职责、正式契约及缺失/单位/来源语义，再进入已有对应分类。新物性模型使用已有指标目录和模型注册表；新来源使用既有 Provider 接口与 `providers/`；跨功能组合进入核心现有流程，不另建平行链。

现有目录能容纳新功能时不增顶级目录；不得创建 `versions/`、`src/`、`app/` 或新的项目外壳。未来上层 Agent 尚未定义，当前不建空目录、接口或框架。



结构查询目录：核心系统/结构查询/存放数据结构、接口和显式字段adapter；插件/化学计算/RDKit结构检索插件.py负责本地算法。配方生成/组成签名.py负责公共纯质量签名。原目录没有这些独立公共职责，不把检索塞进身份处理插件。

分子属性目录仅保存公共契约；插件/化学计算/RDKit分子属性计算器.py负责2D算法、catalog及旧长表公开适配。核心配方研发流程按计划调用，由默认装配层选择未注入的计算器，复用StructureCandidate/adapt_candidates而不执行搜索。普通描述符和确认批次各自转换旧输出；用户规则适配进入既有属性注册表/执行器，不建立平行规则体系。

控制器委托 `核心系统/用户候选流程.py` 和 `核心系统/SeeThrough复现流程.py`，沿用功能获取器与唯一默认装配；未建立新的工作流框架。`软件界面/论文运行上下文.py` 只处理 session 中的补充表 run_id。旧审计以审计区 README 标记冻结日期，不作为当前说明。
