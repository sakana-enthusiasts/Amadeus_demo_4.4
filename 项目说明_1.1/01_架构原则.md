# 架构原则

这些是项目长期规则，不是新功能清单。当前实现及例外见 [04](04_当前架构.md) 和 [07](07_技术债与遗留预留.md)。

## 单一职责

一个模块承担一个明确职责。功能插件保持单一职责，不为任务方便塞入无关逻辑；需要组合多个功能插件时，由核心流程编排。物性模型只计算自己的指标，Provider 只适配自己的外部来源。

## 可替换实现与稳定公共能力

优先依赖正式接口、注册表和数据契约。更换公开数据库 Provider 不应修改 EvidenceResolver，更换黏度模型不应修改折射率模型，更换存储后端不应修改使用证据的业务模块。若现有耦合阻碍替换，记录技术债，不继续扩大耦合。

当前公开证据层是重要实例：`核心系统/公开证据/` 保存公共契约与能力，`插件/公开数据/providers/` 保存具体来源；核心不依赖具体 Provider，Provider 通过接口注册，彼此不互调。配方物性也是实例：汇总通过模型注册表选择 `预测(配方, 上游)` 策略，模型依赖由声明与汇总调度表达，而非互相调用。

## 默认装配边界

默认具体实现只在明确 composition root 选择；工作流的唯一默认装配点为 `核心系统/默认装配.py`。核心工作流决定何时调用能力，通过公共获取器或专用接口使用实现；不导入具体功能插件类自行构造。装配只负责注册和默认依赖选择，不执行业务、不读用户数据、不联网，也不保存运行状态或成为 Service Locator God Object。

StructureSearch、MolecularPropertyCalculator、PublicDataProvider、EvidenceRepository 与物性模型继续使用专用 Protocol/ABC，不为统一外观强塞进通用插件 ABI。物性模块内部的模型注册工厂仍属于其专用策略装配；工作流通过默认装配工厂或显式注册表选择它。

## 明确依赖方向，禁止循环

上层流程/调度 → 公共接口 → 具体模块/插件。装配点可以导入具体实现进行注册；普通公共能力不得因此反向依赖具体上层流程。底层不依赖 UI、UI session state、未来 Agent 或具体研究计划。

禁止功能插件调用其他功能插件的私有实现，禁止 Provider 互相依赖内部实现，禁止插件→私有方法→临时文件→反向调用的链条和循环依赖。现有兼容反向转发入口如实记录，不作为新增依赖范例。

UI 只使用核心公开入口及设置，不 import 具体插件、不实例化执行插件、不穿透控制器的插件管理器。用途配置元数据位于设置模块，用途算法留在正式功能插件；通用规则引擎维护契约与执行器，默认属性/规则预设只由设置工厂维护。

配方研发流程只编排现有能力。公开证据执行桥、分子标准化、扩展描述符及未来 pKa/logD、ADME/QSPR 等独立能力有正式数据契约和可替换实现时，使用自己的专用模块/Protocol，由流程显式调用；不得将模型实现堆入流程，不提前创建空接口。

## 跨模块必须经过稳定契约

传递正式数据结构、接口返回值或明确声明的上下文，按字段名和语义关联。不得依赖私有变量、未声明字典字段、DataFrame 偶然列位置、临时 CSV、内部缓存、UI session state 或具体数据库表结构。

字段变化优先扩展正式契约并确定兼容语义，不让多个模块分别猜测。当前固定结果标识属于历史约定，不是新建临时文件总线的授权。契约中的单位、条件、来源、身份、缺失和错误含义必须一起保留。

## 缺失与证据不可伪造

未知使用 unknown/missing/unavailable、None 或现有明确状态表示。不得填零、平均值、合理猜测的实验值；不得把预测伪装实测、summary 伪装 measured、未知风险解释成低风险。

证据保留来源、条件、单位、化学形式、类型和原始记录关系。不覆盖、不静默平均、不隐式消除冲突。显式近似假设和未量化不确定度随结果传播；程序可计算不等于实验效果或安全性已验证。

## 模块独立存储，外部通过接口访问

允许公开证据等模块独立管理 Repository 和 raw cache。其他模块通过 `EvidenceRepository` 的 add/query/close、Resolver 采用结果及公开聚合入口获取数据，不读取内部 SQLite/DuckDB 表或 Parquet payload 结构。更换后端的影响应限于实现和装配点。

## 沿用现有职责，不重复建设

现有接口、注册表、数据契约能够表达能力时优先扩展。不得创建第二套平行接口、数据模型或流程。新文件进入已有匹配分类；只有确实无法表达新的独立职责且任务授权时才新增分类，不为了单个任务创建代码层级或新顶级目录。

Target Profile 通过纯指标绑定与执行计划接入现有研发编排；硬约束在现有发现约束插件评价，目标只进入现有 Pareto 排序器。legacy 与规格硬约束取 AND，直接冲突预检报错；report_only 不改变可排序资格，disabled 不产生执行要求。

若当前任务与这些原则冲突，先报告具体冲突，不自行绕过。未来规划、预留接口和科研资料不构成实施授权。

分子属性采用工具无关公共结果契约→具体RDKit实现→核心装配。计算属性、用户/公开实测值及配方物性分别保留；molecular_weight仍绑定物质记录，不静默改为MolWt。正式核心指标与未审查扩展报告分开，molecule objective没有多成分聚合契约，明确unsupported。旧长表和确认批次通过公开legacy_descriptors API适配，不互调功能插件私有方法。



## 功能编排 ABI 与专用接口

基础插件接口的通用执行方法只承担历史/通用功能插件编排 ABI。StructureSearch、MolecularPropertyCalculator、PublicDataProvider、EvidenceRepository 和物性模型继续保留专用 Protocol/ABC。新能力优先使用与能力对应的契约，不强迫所有能力进入 God Context。

功能插件以自身稳定插件标识为 canonical ID；alias 必须显式声明。canonical、alias 和二者交叉碰撞全部拒绝，不允许静默覆盖；替换使用显式 API，并原子校验和保留或更新 alias。

## 持久与临时目录

正式 run 生命周期由现有运行数据管理器管理，持久运行写入 `数据/运行记录/run_YYYYMMDDTHHMMSSZ_<随机ID>/`。真正临时文件使用系统 TEMP/TMP 并自动清理；不得按毫秒时间戳在项目根建目录，也不得用 ignore 数字目录掩盖生成源。`.cache/temp/` 仅供明确保留的调试缓存，默认不创建，不作为数据总线、插件通信或正式运行结果。

显式原子保存是例外：为保证文件替换原子性，Target Profile JSON 的短期临时文件与用户指定目标文件同目录，完成或失败后清理；不作为持久运行产物。
