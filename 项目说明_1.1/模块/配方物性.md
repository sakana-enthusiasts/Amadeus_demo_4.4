# 配方物性

独立指标模型通过注册表选择，核心编排功能汇总，用途层读取统一结果。当前颅骨透明化用途层是应用层，不代表底层物性模块只能服务颅骨透明化；模型不依赖该用途目标或未来 Agent。

## 当前分工

`插件/配方物性/配方物性接口.py` 定义 `配方输入`、`物性结果`、`物性模型接口`、`输入不可用` 和有限数校验。`配方物性汇总.py` 定义 `模型注册表`、`创建默认模型注册表`、输入适配与 `配方物性汇总插件`。折射率、黏度、扩散、渗透、水活度的指标接口和模型已真实存在。

物性汇总的职责是实测优先、配置核验、模型选择、依赖递归和统一结果；不计算用途总分，不生成候选，不内置用途毒理或递送结论。模型是策略对象，使用 `预测(配方, 上游)`，不调用功能插件或其他指标模型。

工作流通过 `核心系统/默认装配.py::创建配方物性汇总(注册表=None)` 构造汇总；默认管理器接受 `物性注册表`。研发原有 `注册表` 参数保留，自检、搜索和最后验证共用该模型注册表。若同时注入功能获取器与注册表，注册表仅覆盖本次物性汇总，不修改调用方管理器；未提供注册表时直接使用注入获取器的汇总。模型接口和模块内部默认策略工厂不变。UI 通过 `核心系统/默认装配.py::创建默认物性模型注册表()` 获取独立注册表；该薄工厂不执行模型或读取用户数据。

## 输入与配置

`配方输入` 是 frozen dataclass，含成分 tuple、条件 Mapping、参数 Mapping、配方编号；冻结属性不等于嵌套 Mapping 都深度不可变。`分数(字段)` 检查每行有限数、0–1、总和为 1（1e-6 舍入误差），计算时只保留正分数组分。零分数组分仍须有分数字段；正分数组分须具备模型需要的物性。`温度K()` 要求明确 `温度_C` 且高于绝对零度。

汇总上下文接受 `成分` DataFrame/记录列表、`物性条件`、`物性模型参数`、`物性模型选择`、`配方编号` 和 `配方设置` 实测数据。直接汇总只把明确 `v/v%`、`% v/v`、`体积百分比` 转为体积分数，把 `mol%`、`摩尔百分比` 转为摩尔分数；裸 `%`、质量百分比和 mM 不当体积分数。

这不意味着全项目不会质量/体积/摩尔换算：完整 `配方输入组装插件` 已支持基于分子量、匹配温度的密度及明确投料单位进行换算，见 [接口与数据契约](../03_接口与数据契约.md)。两个入口的校验力度不同：完整组装会检查相态、密度/RI/黏度温度及 RI 波长；直接公式输入部分一致性须由来源确认，模型警告明确保留该限制。

默认设置 `设置/配方物性设置.py` 将五指标都设为 `measured_only`；研发流程另有 `研发默认模型` 显式启用公式，不能将两个默认入口混为一谈。用途流程支持批次配置字典或 JSON 对象文本，顶层上下文覆盖批次；补基础用途温度后，显式条件覆盖它。配方构建页面已有模型、成分物性、实测、条件和参数录入。

模型选择可为：

- `measured_only`：缺实测时返回“待补实测”。
- 固定方法：只尝试该模型，不暗中换模型。
- `auto`：按自动优先级降序及方法名排序尝试，保留此前不可用原因；不比较虚构置信度，不自动训练。

所有模式先校验配置，再优先使用有效实测。无效已填写实测返回“输入无效”，不会用预测覆盖；未知指标/方法直接报配置错误。

## 已注册指标与模型

| 指标 / 方法 | 关键输入与当前边界 |
| --- | --- |
| 混合折射率 / `lorentz_lorenz` | 体积分数、纯物质RI；均匀液体、体积可加近似，直接模型不逐行验证输入温度/波长一致性 |
| 混合黏度 / `ideal_log` | 摩尔分数、纯物质黏度_mPa_s；理想对数混合，忽略相互作用 |
| 混合黏度 / `grunberg_nissan` | 同上，唯一成分键、非零组分对完整 Gij、匹配参数温度；多元两两项近似，auto 优先级 10 |
| 混合黏度 / `cheng_glycerol_water_2008`（`黏度/Cheng_2008.py`） | 质量分数、水/甘油 CAS、0–100°C；仅甘油–水经验式，不推广到其他体系，auto 优先级 5 |
| 自由扩散 / `stokes_einstein` | 声明上游混合黏度、探针水动力半径_nm、温度；指定探针在均匀连续介质的自由扩散，不是候选分子/组织有效扩散 |
| 渗透压 / `ideal_osmotic` | 显式溶剂/溶质角色，溶质摩尔浓度_mol_L、范特霍夫因子、温度；理想稀溶液初筛，非生理安全结论 |
| 渗透压 / `osmotic_coefficient` | 理想压力输入及当前体系有效渗透系数；用户提供系数，不自动拟合，auto 优先级 10 |
| 水活度 / `ideal_water_activity` | 摩尔分数、唯一水成分键；aw = xw，不直接推断脱水程度 |
| 水活度 / `water_activity_coefficient` | 同上及水活度系数；aw = gamma_w × xw，只支持 0–1，auto 优先级 10 |

黏度 auto 的当前顺序为 Grunberg–Nissan、Cheng 甘油–水、理想对数混合。缺 Gij 不是一定直接回退理想模型，甘油–水可先用 Cheng。

标准单位为混合 RI 无量纲、黏度 `mPa·s`、自由扩散 `m²/s`、渗透压 `Pa`、水活度无量纲。扩散公式内部把 mPa·s 转 Pa·s、nm 转 m；渗透公式把 mol/L 转 mol/m³。缺范特霍夫因子不默认为 1，实测 osmolality 不可直接填入 Pa 渗透压字段。

实测字段依次为 `混合液实测RI`、`混合液实测黏度_mPa_s`、`实测自由扩散系数_m2_s`、`实测渗透压_Pa`、`实测水活度`；实测来源可用 `物性实测来源`。代码并没有从这些输入自动得到实测不确定度，结果明确提示未提供。

## 结果、依赖与错误

`物性结果` 含 `指标/值/单位/状态/方法/模型版本/置信度/适用范围/警告/数据来源/不确定度/依赖`，检查成功状态有数值、数值有限、置信度范围与非负不确定度。汇总追加配方编号、请求方法、条件和模型参数。公式未校准时置信度/不确定度为 None；Cheng 保留其文献来源及未量化区间警告，不伪造已校准区间。

依赖由模型声明 `依赖指标`，汇总递归按需计算一次，并检测未注册依赖与环。Stokes–Einstein 保留上游黏度完整结果并传播警告；替换不依赖黏度的扩散模型时无需继续声明该依赖。

缺失/不适用用 `输入不可用` 表示；汇总实际捕获该异常及 `ArithmeticError` 并记录无法使用原因，固定方法失败也返回“无法预测”。输出指标/单位/方法/版本不符合注册契约报错，未知配置、重复方法、单位不一致和循环依赖也报错。不能沿用旧说明声称所有程序错误都绝不进入回退。

## 用途与持久化

核心评估在物性汇总之后生成用途摘要、特征和约束。实测与预测 RI 分别保留，用途通过采用 RI 计算与配置目标的偏差。`用途配置["物性约束"]` 接受逐指标最小/最大，输出通过、不通过、未知、未设置阈值及证据状态。

组织有效扩散、滞留、washout、局部和全身毒性固定保持未知，不能作为安全通过或加分。用途 `运行用途评估` 将独立物性表与用途约束按批次保存；警告/依赖/条件/参数编码 JSON。该存储覆盖同批次结果，不是不可变的模型运行历史。

兼容 `颅骨透明化用途运行器.运行(...)` 位于 `核心系统/配方评估流程.py`，旧用途插件模块仅 re-export；正式用途功能实现在 `颅骨透明化功能插件.py`，不依赖核心编排；用途元数据与默认配置在 `设置/颅骨透明化用途设置.py`，原功能模块继续重导出公开名字。直接用途插件必须由核心/调用方提供上游结果，不能重复隐式计算多个功能插件。

## 新增或替换模型的现有扩展方式

在已有指标目录实现其指标接口，声明唯一方法、模型版本、适用范围、标准单位，实现 `预测(配方, 上游)` 返回 `物性结果`。通过 `模型注册表.注册(实例)` 并注入 `配方物性汇总插件(注册表)`，或在默认工厂显式注册。方法 `auto/measured_only/measured` 为保留名；同指标同方法重复注册禁止。修改其他指标或用途阈值不应成为换模型的前提。

配置方法名与自动优先级，必要时声明依赖。功能组合仍在核心；不因为未来 AI/Agent 设想增加新的模型层。实验校准模型必须有真实产物再实现。

相关验证：`配方物性测试.py` 核验公式单位、回退、实测优先、依赖/循环、扩散替换时其他指标不变、批次持久化和页面配置；`配方研发测试.py` 核验完整组装与研发接入。局部比例细化已修复并有回归覆盖；物性当前实际未解决限制见 [07](../07_技术债与遗留预留.md)。
