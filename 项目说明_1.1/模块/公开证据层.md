# 公开证据层

`核心系统/公开证据/` 提供稳定公共契约与解析能力，`插件/公开数据/providers/` 提供具体来源策略，公开聚合功能插件由核心入口调用。公开物性独立于旧 descriptor 宽表，通过默认关闭的执行桥进入派生候选及现有配方计算。

## 契约和入口

`核心系统/公开证据/` 不导入具体 Provider 或功能插件。`PublicDataProvider` 是策略对象，`ProviderRegistry` 注入来源；各 Provider 不互相导入或查询。流程控制器只调用 `公开证据聚合插件`。

`PropertyEvidence` 保存值、单位、界限、条件、化学形式、类型、方法、模型、适用域、不确定度、来源、文献、抓取时间、解析版本和原始响应 ID。各记录独立保存，不 pivot、不覆盖、不自动平均。`extra` 保留无法映射的原始字段，raw cache 保留完整响应。

`EvidenceResolver` 根据 `EvidenceRequest` 生成单独的 `ResolvedProperty`。对于请求明确指定的温度、pH、溶剂或形式，默认不把未知条件当成匹配；请求未指定的字段不作该项过滤，但等优先级证据条件不一致仍会形成冲突。`measured_only=True` 排除预测、衍生及汇总。等优先级证据值相差超过默认 10% 或条件/形式不同，返回 `conflict`，不自动采用；可明确指定来源或更精确的条件。界限、范围及未解析文本保留为证据，不能直接采用为确定值。最终结果保留全部匹配证据的原始 ID。

温度用 K，压力用 Pa，pH 无量纲。常见质量浓度、密度、黏度和表面张力单位可转换，同时保留原始值与单位。百分比、摩尔浓度、对数值和没有明确量纲的字符串不作猜测转换。

化合物 `compound_id` 必须是调用方提供的稳定身份标识。同一盐、水合物或立体形式应使用独立 ID；不应把不同运行中的局部行号当成全局化合物 ID。公开证据绑定 `observed_structure` / `chemical_form`。RDKit parent 清理只生成独立副本，记录标准化版本，不覆盖原件；这不是新分子预测软件。

## 存储与缓存

安装主项目依赖后，再安装公开证据后端：

```powershell
python -m pip install -r requirements-public-data.txt
```

新入口默认 `DuckDBEvidenceRepository`，可选 `sqlite`、`parquet`，或直接注入 `EvidenceRepository` 实例。DuckDB 可用 `export_parquet(path)` 导出长表快照；Parquet 后端追加不可变分片并用 Arrow 条件下推查询。SQLite/DuckDB 使用条件查询列和索引，其他字段以 JSON 保存。重复抓取/重解析保留独立证据，同一原始响应在同一解析版本下重复执行会去重。

默认存储目录为 `数据/软件数据库/公开证据/`，与现有 `数据管理接口` 分离。原始响应默认存于独立 SQLite raw cache，包含来源、URL、源编号、抓取时间、状态码、响应 SHA-256、抓取时解析版本和完整正文。请求头及密钥不写入缓存。先保存响应，再调用解析器；失败 HTTP 响应也保留，但 429/5xx 不作为缓存命中。

同一来源跨客户端实例共享进程内限流，默认每秒最多 4 次请求；429/503 等有限重试并遵守有上限的 Retry-After。在线缓存默认有效 7 天；离线重解析允许读取过期原件。修改解析器版本后，以同一候选和来源执行 `允许网络公开查询=False`，即可从目录和响应缓存重新解析，不重新访问网站；新证据携带新版本，旧证据仍保留。多进程批量任务需要外部协调请求预算，批量任务不能绕过来源请求预算。

## 来源能力

| 来源 | 当前实际实现 | 边界 |
| --- | --- | --- |
| PubChem | observed identity 的唯一 CID 解析；PUG REST 结构、分子式、分子量、电荷、XLogP、TPSA、HBD/HBA 等；PUG View index 动态发现实验物性 heading；独立 GHS 提示 | REST 是计算证据；第三方 annotation 默认汇总，只有明确测量说明才标为 measured。Solubility 不默认水介质；非水记录使用 solubility。无法安全数值解析的文字保留原件。 |
| CompTox | DSSTox 身份；chemistry；experimental/predicted PhysChem；ToxValDB/ToxRefDB；bioactivity；ADME/IVIVE | key 只从 `COMPTOX_API_KEY` 或客户端注入读取。无 key 返回 unconfigured。OPERA/TEST/ChemPROP 等按 API 返回的 modelName 保留，不伪造本地模型。毒理、生物活性、毒代领域记录完整保留为 summary 记录，不自动转换成现有实验毒理匹配条件。 |
| NIST WebBook | CAS/明确 NIST ID；长表中的熔沸点、临界量、可识别热化学量；明示链接的熔沸点单条实验列表 | 平均值为 summary，实验行才是 measured。未识别表、Antoine 系数、光谱和 fluid 接口原文仍在 raw cache；当前不宣称已实现这些全部端点。 |
| ThermoML | 官方 XML 文档；namespace；化合物匹配；逐点物性；约束/变量；相态、方法、文献及多种 uncertainty XML | 需要提供官方文档 URL，以及文档内 org number 或可唯一匹配的 InChIKey/CAS。没有虚构按 CID 搜索 ThermoML 的 API。未知属性使用源命名空间保存；未知条件/组成保留结构化值及 XML。混合物另建身份，不当成成分纯物性。 |

缺失能力返回 `unsupported`。身份歧义不选第一条；一个来源失败不阻止其他来源。候选 SMILES 与 InChIKey 不一致时记录 `identity_conflict` 并隔离该候选，不修改原件、不让整批流程中断，也不采用该候选的历史物性。离线/模拟验证不代表 CompTox 真实认证已经验收。

## 调用示例

```python
from pathlib import Path
from 核心系统.流程控制器 import 创建颅骨透明化筛选流程控制器

controller = 创建颅骨透明化筛选流程控制器(Path.cwd())
result = controller.执行公开证据查询({
    "公开候选": [{
        "compound_id": "ethanol:neutral", "化学名称": "Ethanol",
        "CAS": "64-17-5", "PubChem CID": "702", "chemical_form": "neutral",
        "observed_structure": "CCO",
    }],
    "公开数据源": ["pubchem", "comptox", "nist"],
    "公开能力": ["properties"],
    "允许网络公开查询": True,
    "允许使用缓存": True,
    "证据存储后端": "duckdb",
    "物性请求": [{
        "compound_id": "ethanol:neutral", "property_id": "density",
        "chemical_form": "neutral", "temperature": 298.15,
        "measured_only": True,
    }],
})
evidence = result["证据"]
resolved = result["物性采用结果"]
audit = result["查询日志"]
```

数据源注册表、证据存储、原始响应缓存可分别通过上下文键 `数据源注册表`、`证据存储`、`原始响应缓存` 注入；注入实例由调用方关闭。GHS 旧导入名只保留兼容外观，控制器的旧 PubChem 插件标识指向同一个聚合实例。旧页面输出 CSV 仅是报告视图，不是新证据存储；旧 CSV 缓存中可校验的原始 JSON 会一次导入 raw cache 并重解析，旧文件不删除、不修改。GHS 不参与 A/B/C/D 条件匹配或自动淘汰。

## 新增或替换实现

新增来源实现 `PublicDataProvider` 的 capabilities/resolve_identity/fetch_properties，按来源能力实现其他 fetch；在现有 ProviderRegistry 注册唯一 provider_id，通过聚合入口的 `数据源注册表` 注入。核心证据目录不导入来源实现，Provider 不互相查询。

替换存储实现 `EvidenceRepository.add/query/close`，通过 `证据存储` 注入，业务继续消费 PropertyEvidence/ResolvedProperty，不访问 SQL 内表或 Parquet 分片。原始缓存同样通过公开缓存接口与注入点使用，不将缓存数据库当通信协议。聚合的 `证据选择器` 上下文键和执行桥的 `resolver` 参数均支持注入；默认使用现有 EvidenceResolver。

未知条件、来源能力缺口、身份冲突和证据冲突保留状态。未解析文字保留证据和原件，不冒充确定数值。旧候选编号回退为全局身份的风险亦见 `07`；新调用明确提供稳定形式身份。

## 执行连接边界

PublicEvidenceExecutionBridge 已实现，只通过 Repository.query 与 Resolver.resolve 消费正式 ResolvedProperty，不读取内表、不修改用户输入或证据。独立执行视图保存采用条件与出处；首版限四类组装输入，默认 off、cache_only 不调用 Provider，fetch_missing 显式且先检查硬上限。既有独立查询入口保持兼容。详见 [执行桥](公开证据执行桥.md)。
