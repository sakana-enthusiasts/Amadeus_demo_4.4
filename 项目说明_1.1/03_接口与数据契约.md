# 接口与数据契约

当前契约依实际代码记录；公开接口与内部实现区分如下。模块详见 [公开证据层](模块/公开证据层.md)、[Target Profile](模块/Target_Profile.md)、[配方物性](模块/配方物性.md)。

## 功能插件、注册与上下文

`插件/插件接口.py` 的 `基础插件接口` 提供 `插件标识` 与抽象 `执行(数据上下文: Any) -> Any`。实际结果可为 DataFrame、字典、元组或 Path，不存在已实现的统一消息容器。`未启用插件` 只返回状态，不生成虚构结果。

`核心系统/插件管理器.py` 公开 `注册插件(实例, 别名=())`、`替换插件(实例, 别名=None)`、`获取插件(ID)` 和 `注册列表()`。注册校验基础插件接口实例及稳定非空插件标识，以实例插件标识为 canonical ID；重复或交叉占用拒绝。替换要求已注册且相同 canonical ID，默认保留 alias，显式别名序列可更新；失败不改变注册状态。查询支持 alias，未知 ID 的 KeyError 包含可用注册；列表是诊断快照，私有表不对外开放。历史 PubChem查询 是公开证据聚合的 alias，补充数据2表格导入 是普通表格导入的 alias。它不承担自动发现、依赖调度或业务生命周期。

默认装配公开 `创建默认物性模型注册表()`、`创建默认插件管理器(*, 物性注册表=None)`、`创建配方物性汇总(注册表=None)`、`创建默认结构检索器()`、`创建默认分子属性计算器()`。每次工厂调用产生独立实例，无全局单例；原控制器工厂名称与两个 legacy aliases 保持兼容。

研发的预测完整配方、数值自检、验证与发现入口接受兼容默认值的 `获取插件: Callable[[str], 基础插件接口] | None`。`装配工作流插件获取器(获取插件=None, *, 注册表=None)` 仅选择依赖：未注入则创建默认管理器；注入获取器则复用。显式注册表优先决定本次物性汇总，其他插件仍来自注入获取器，不修改调用方管理器。单次发现的自检、候选评价、细化和最后 Benchmark 共用同一获取器，不逐步重建管理器。Profile 预检通过物性汇总公开的 `注册表.指标列表()` 获取可用指标；替代汇总须保留此能力。

用途评估沿用获取器参数；生成确认批次描述符、运行用途评估和确认后自动处理新增可选关键字获取器，旧调用保持可用。StructureSearch 与 MolecularPropertyCalculator 继续单独注入，未提供且实际需要时才由默认装配选择 RDKit。PublicDataProvider、EvidenceRepository 和物性模型专用契约不变。

用户筛选上下文主要含数据管理器、文件名/bytes、字段映射、应用配置/用户设置和运行编号。用途上下文主要含成分、用途配置、HSP参照、配方设置、实验记录、配方编号；物性选择/条件/参数有明确键。研发输入为物质记录列表、配方定义/生成配置、约束和配方证据。新字段必须在正式上下文说明中声明；不得从页面状态或临时文件猜测。

控制器新增 `执行人工身份确认(数据上下文)`、`重新生成筛选结果图表(数据上下文)`，分别获取 canonical `人工身份确认`、`筛选结果图表` 并转发。上下文默认使用控制器数据管理器，允许页面传入选定 run 的管理器；其余上下文字段与插件返回保持原样。人工身份确认在默认装配显式注册。

`执行毒理公开数据查询(毒理会话)` 委托 `毒理分析.运行毒理公开数据查询(数据管理器, 获取插件, 毒理会话)`，来源选择、空候选校验及批次补齐归属毒理流程；当前仍仅查询 PubChem GHS。

## 候选上传、用途设置与规则预设

`核心系统/候选表输入.py::读取候选上传内容(文件名, 内容)` 返回 DataFrame；公开 `安全文件名`、`最大上传字节数` 与 `支持扩展名`。仅支持 UTF-8/UTF-8-SIG CSV 和 XLSX，上限 2 MB；检查文件名、扩展名/签名、重复/空列名及空表，保留原校验异常语义。XLSX 空单元格表头同样明确拒绝。模块不保存、不映射字段。UI 预览与导入插件复用同一函数；旧 `通用候选表导入插件.读取上传内容` 与 `安全文件名` 是同一函数别名。

`设置/颅骨透明化用途设置.py` 是用途标识、名称、配置版本、成分角色、实验终点和默认用途配置的唯一来源；功能插件仍重导出这些公开名字。默认配置每次返回独立字典，不移动算法。

`设置/规则注册设置.py` 公开 `创建默认属性注册表()`、`创建默认规则注册表()`，每次返回独立注册表，保留默认规则顺序、阈值、启用状态和 CORE_METRICS。引擎内 `属性注册表.默认()`、`规则注册表.默认()` 仅为兼容入口，延迟调用唯一工厂并保留子类构造语义；新生产代码使用显式工厂。规则执行器未传注册表时也委托该工厂，不保存第二份预设。

## 共用记录与文件数据管理

`核心系统/数据格式定义.py` 定义三个 Pydantic 模型：`化学候选记录`（可缺失候选、名称、CAS、来源及现有 RI/水合/pH/Hansen 字段和指定别名）、`数据批次`（批次标识、数据类型、来源、附加信息）、`毒性证据记录`（必填候选编号/终点/实验值或预测值，其他实验条件/来源可缺失）。候选和毒性模型 extra=allow，保留原字段；不等于所有 DataFrame 已强类型化。

`数据管理接口` 公开论文读取，中间/最终/筛选结果读写、软件数据库读取、结果存在检查、导出及用户原件保存；文件实现的读操作返回 DataFrame，保存返回 Path。抽象契约同时声明软件数据库写入、目标可写检查，以及项目根/论文原始数据/软件数据库/导出目录路径能力；文件实现提供这些能力。运行创建与 run_id 不要求所有文件管理实现提供。

论文按 Excel 读取；软件数据库 CSV 按字符串保留空串；结果 CSV 保留空串但可推断列类型；保存 UTF-8 BOM、不写索引。最终结果读取先模型后筛选。内部 `_保存表格/_读取表格`、目录属性和路径拼接不是跨模块通信协议。生成 CSV 标识的读、写与存在检查共用标准化规则：拒绝空值、`.`、`..`、包含 `..`、斜杠、反斜杠、盘符和绝对路径；保留中文、英文、数字、下划线和既有 `.csv` 名字。软件数据库表格也使用同一校验；论文原件路径和 run 布局不变。此约束不是全文件系统沙箱。

`运行数据管理器` 公开 `创建运行(应用配置=None, 输入文件名=None, 元数据=None, 运行类型="用户候选", 输入来源=None)`、激活运行、运行目录/当前编号及带可选 run_id 的读写。输入文件名若提供必须安全，CLI 不伪造上传文件。run_id 匹配 `run_YYYYMMDDTHHMMSSZ_<id>`；创建前验证元数据 JSON，路径检查覆盖创建/激活/查询。元数据记录类型、输入来源、可选应用配置与创建时间。激活后产物进入 `数据/运行记录/<run_id>/`，公开中间/筛选/模型/导出目录同步指向该 run；带 run_id 的读取或活动 run 缺失均不会回退全局结果。未激活的管理器仅为旧结果读取兼容。软件数据库/确认目录仍全局。固定结果标识是现有兼容约定，新开发不能引入临时 CSV 总线。

候选编号在运行内标识行；跨运行保留 run_id，确认批次保留批次编号、来源和成分键。全局公开 compound_id 应稳定地区分化学形式，不将本地行号当全局化合物身份。

## 公开证据正式接口

| 公共接口/结构 | 当前能力 |
| --- | --- |
| `PublicDataProvider` | capabilities、resolve_identity、fetch_properties；hazard/bioactivity/toxicokinetics 默认 unsupported，可由来源实现 |
| `ProviderRegistry` | register/get/providers；重复 provider_id 拒绝；通过接口注册替换来源 |
| `CompoundIdentity` | 稳定 compound_id、observed/parent 结构、形式、InChIKey、来源标识与标准化版本 |
| `PropertyEvidence` | 值/单位/界限/条件/形式/类型/方法/模型/来源/文献/抓取/解析/raw 关系和原始 extra；类型为 measured/predicted/derived/summary |
| `EvidenceRequest` | 请求身份/属性、形式/结构、温度/pH/压力等条件及容差、来源、measured_only、未知条件策略 |
| `ResolvedProperty` | request/status/selected/evidence_ids/conflicts/reason；不是丢弃出处的裸数值 |
| `ProviderResult` | 状态、证据 tuple、身份、消息、raw IDs 和缓存命中 |
| `EvidenceRepository` | add(evidence)、query(compound_id/property_id/sources/temperature_range)、close 和上下文管理 |
| `EvidenceResolver` | resolve(request, evidence)，条件/单位标准化后形成采用、missing 或 conflict |

公共条件匹配、单位标准化、身份标准化和冲突解析位于核心证据目录，不依赖具体 Provider。具体来源位于 `插件/公开数据/providers/`，client/parser/mapping/provider 属来源实现，不是别的 Provider 的可调用业务接口。

Repository 当前有 SQLite、DuckDB、Parquet 实现；connection、SQL 表/索引、Parquet payload 与分片布局属于内部，业务只访问 Repository/Resolver 和聚合返回结构。DuckDB 的 export_parquet 是显式后端扩展，不要求使用证据的模块知道它的内部表。

控制器公开查询通过聚合插件；上下文可注入 `数据源注册表`、`证据存储`、`原始响应缓存`，调用方关闭注入资源。Resolver 可通过 `证据选择器` 注入；执行桥也接受同一 resolve(request, evidence) 接口。注入资源由调用方关闭。

公开证据不覆盖/平均；不同条件、形式和类型保持独立，限定值/未解析原文不当确定值；未知请求条件不自动匹配。公开证据不写回原 descriptor 宽表。显式执行桥将四类可采用证据投影到独立候选视图，供现有筛选及配方组装使用；原记录不改。raw cache 的 SQLite 布局是缓存内部实现，其他模块不读表。

## Target Profile

`核心系统/目标规格/` 公开 Criterion、TargetProfile、ProfileValidationError、import/export_profile_json、save/load_profile。指标 role 为 hard_constraint/objective/report_only/disabled，目标 mode 为 minimize/maximize/target/range；支持 scope 和缺失/证据要求校验。

结构只保存规格，不保存候选、实验、Benchmark 或模型参数；独立于插件/工作流。JSON 拒绝未知/重复字段、非法数值和枚举；编辑返回新对象，保存显式路径且默认拒覆盖。代码允许 molecule/formulation/delivery/experiment scope，后两个当前没有执行绑定。

`指标绑定.py` 的 MetricBinding 声明 scope、来源字段、标准单位、证据类型能力及可执行 role；`执行计划.py::compile_profile(profile, legacy_constraints=..., available_properties=..., model_selection=...)` 返回不可变 ExecutionPlan 和可导出的预检结果，不执行模型或查询。scope 省略时由绑定明确确定；显式 unit 必须与标准单位相同，不猜测或隐式换算。数值绑定不接受布尔 equals 执行，契约本身仍保留 equals。

`运行发现模式(..., 目标规格=None)` 接受正式 TargetProfile；流程将 ExecutionPlan 通过插件上下文 `执行计划` 传给现有分子筛选、配方约束及候选排序。结果保留原始规格/version、计划、预检、全部配方评价、排除分子评价及最终 objectives；每条 `目标规格评价` 含原始值/单位、合格值、状态、缺失原因、role、来源/类型/条件和硬判断或目标变换。molecule 结果按物质保留，不隐式聚合为配方 objective。

规格硬约束使用各 criterion 的 missing_policy，独立于 legacy 全局缺失策略；两者取 AND，直接数值冲突在预检报错。Profile objectives 优先，否则使用 legacy 优化目标/默认 RI+黏度。目标缺失 keep_unknown 保留在 `未知未排序候选`，exclude 取消可排序资格，两者均不伪造向量。只有 objective 进入 Pareto；report_only 不影响资格或向量，disabled 不进入执行要求。目标变换为 value、-value、abs(value-target)、区间外距离/区间内零；tolerance 不自动变成硬约束。

## 单分子计算属性契约

`核心系统/分子属性/`公开CORE_METRICS、MolecularMetric、MolecularPropertyResult、CandidateMolecularProperties、MolecularPropertyCalculator。结果保留metric_id/value/unit/value_kind/status/method/engine/engine_version/source/canonical_structure/structure_format/reason/warning/descriptor_name；available仅接受有限数值，失败value=None且保留原因，可严格JSON序列化。状态为available/invalid_structure/unsupported/calculation_failed。

发现入口增加`分子属性计算器=None`和`扩展描述符报告=None`（显式RDKit原始名称列表），复用`结构字段映射`，无Structure Query也可计算。ExecutionPlan.required_molecular_metrics只收集启用正式指标。确定性结果 `value_kind="computed"`；11项绑定的历史字段 `evidence_types` 表示允许的值类别，不仅是外部证据类型。any 接受 computed；measured_only、measured_or_predicted、predicted_allowed 不接受 computed，预检拒绝不满足的要求。PropertyEvidence 仍仅允许 measured/predicted/derived/summary，分子计算结果不写入证据库。候选`分子计算属性`是独立计算命名空间，不读取用户同名字段；运行`分子属性结果`保存结构及全部请求结果。规格评价保留property_status/method/engine/version/canonical和unknown原因。molecular_weight 默认仍读取物质记录；显式启用公开证据桥时，预检允许 measured/predicted，但只有实际补入执行字段的证据才满足对应类型要求；用户原值仍为 unspecified。配方组装公式不变。

用户规则插件上下文可显式注入`分子属性结果`（CandidateMolecularProperties序列，与当前候选编号匹配）和既有`规则注册表`；分子属性记录公开adapter沿用run_id/候选编号/属性编号长表，条件保留完整计算出处，失败当前值None。没有扩大UI或默认启动扩展计算。具体方法/单位见[分子属性](模块/分子属性.md)。

## 配方与物性契约

4.4 新增 `EvidenceBridgeConfig/PublicEvidenceExecutionBridge`，以及 `StandardizationRequest/StandardizedMolecule/StandardizationStep/MoleculeStandardizer`；扩展描述符 `DescriptorRequest/DescriptorDefinition/DescriptorValue/CandidateDescriptorSet/DescriptorCalculator` 位于现有分子属性目录。发现入口增加公开证据配置/执行桥/请求、标准化配置/标准化器、描述符请求/计算器，全部默认关闭。详细投影、条件和结果字段见 [执行桥](模块/公开证据执行桥.md)、[标准化](模块/分子标准化.md)、[分子属性](模块/分子属性.md)。默认装配新增创建公开证据执行桥、创建默认分子标准化器、创建描述符计算器；装配无 I/O。

完整组装含 `配方定义`（物质编号、用量、单位、角色）、`物质库`（唯一编号、分子量及所需物性/来源）、`物性条件`。分数同基准且和为 1；绝对量支持 g/mg/mL/uL/mol/mmol，按体积需匹配温度的密度。输出质量、摩尔、纯组分等效体积分数和显式体积依据，不补溶剂，不用固体 eRI 补液体 RI。返回定义可能已经换为绝对用量；比例细化必须读取 `成分[*].质量分数` 与 `成分键`，用现有 `组装定义` 生成规范化质量分数定义，与粗搜 `已有签名` 比较。

物性正式接口为 `配方输入`、`物性结果`、`物性模型接口.预测(配方, 上游)`、`模型注册表` 与 `配方物性汇总插件.执行`。结果保留值/单位/状态/方法/版本/来源/适用范围/警告/置信度/不确定度/依赖。标准单位为 RI/水活度无量纲、黏度 mPa·s、扩散 m²/s、渗透压 Pa。

新增模型继承现有指标接口、声明方法/版本/单位/适用范围及依赖，注册并配置选择；汇总根据声明计算上游，检测循环，不让策略反调功能插件。实测优先，无效已填实测不静默换预测；缺数据用输入不可用，auto 保留回退原因，未量化置信度/区间保持 None。

## 其他重要边界

通用规则引擎使用属性定义/记录、规则定义/注册与应用配置，按 run_id/候选编号/属性编号关联；它不读公开库内部表。毒理会话区分指定、不作为条件和未知，匹配结果保留证据与缺口，GHS 不参与 A/B/C/D 实验条件匹配。

统一预测与优化抽象接口是合理扩展点，具体 GP/BoTorch 当前未启用。用途兼容运行器、PubChem/CompTox 旧导入名只保留现有行为，不据此建设第二条流程。其他私有调用、场景绑定及历史标识债务见 `07`。

## Structure Query

正式API：StructureCandidate、StructureQuery、SimilarityConfig、StructureHit、StructureSearchResult、StructureQueryError、StructureSearch、adapt_candidates。发现入口新增结构查询=None、结构字段映射=None、结构检索器=None；有查询须显式映射id_field/structure_field/structure_format，发现ID字段为物质编号。结果结构查询结果保存完整快照及result_count/invalid_count/settings；排除分子汇总ID/原因。无效查询抛错，候选无效单独记录。详见[结构查询](模块/结构查询.md)。

配方证据签名以成分键和质量分数为准：ID 唯一、有限正分数、和约等于 1（abs_tol=1e-6），按 ID 排序并 round 到 10 位。搜索定义仅接受质量分数；绝对投料先经原组装换算，不把 20/80 当 0.2/0.8。结构算法语义见[结构查询](模块/结构查询.md)。

## SeeThrough 复现运行契约

控制器的两个补充表入口参数保持原样，返回摘要增加 `run_id`，每次调用创建独立运行。补充数据2依次导入/数值初筛、身份/结构/描述符、Hansen、自动规则、属性与可选标签整合；冲突检测所需补充表3也在本轮从原件导入。

`补充数据2标签验证插件` 读取中间结果 `补充数据2_自动规则筛选记录`，按候选编号一对一追加本轮结构与描述符，再追加可选 final10 验证。自动选择不读标签，未进入结构分析与结构缺失明确区分；不变更阈值。该阶段首次生成唯一 canonical：`数据/运行记录/<run_id>/筛选结果/补充数据2_规则筛选统一记录.csv`，不再向模型结果双写。内部报告/视图使用读取筛选结果；历史读取最终结果仍通过既有回退读取同一筛选文件。

离线结构缓存缺失不隐式联网，返回明确未查询/缺失；只有入口显式启用网络时才能查询。结构/身份缓存和人工参考仍是全局输入能力，正式结果不从旧 run 借用。论文原始输入不修改。
